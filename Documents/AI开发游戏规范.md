# 按照规定的要求进行游戏开发
你是这个游戏项目的编码 Agent。如果我还没说，先问我三件事：

1. 游戏一句话是什么；
2. 用什么引擎和语言（Unity / Godot / FNA / MonoGame / 其他）；
3. 目标平台。

然后按下面所列出的要求搭建和开发项目。每完成一条就提交一次 Git。不要提前写玩法细节。 

## 说明书
- 仓库根目录写 AGENTS.md，再建 CLAUDE.md，内容只有一行 `@AGENTS.md`。
- 按这个顺序写：
    1. 一句话游戏是什么 ，设计从哪份文档开始读（`Documents/concept.md`）
    2. 目录地图：`Documents/ `是设计真相，每个子目录一行用途。
    3. 硬约定：逻辑不碰画面、数值只进 JSON、文案只进表格，如果有新增 .cs，要跑哪个脚本登记（没有就Unity 自动扫描）
    4. 验证命令：改完必须跑什么，跑出什么才算过。
    5. 拍板记录 和 Git 节奏（每完成一个阶段提交一次，提醒我手动push）。
- 拍板要写日期，讨论稿和定稿分开

> 拍板记录把「已确认」「建议（待试玩确认）」「待决定」分开，已确认的写日期，被推翻的规则用删除线划掉并写作废日期，不直接删。
>
> 注意：已确认的设计、实现建议与待决定事项必须分开记录，不能把讨论稿写成已实现功能。拍板过的写明日期。（详细的拍板记录不要全塞进 AGENTS.md，而是放在 Documents/ 里）
>

- AGENTS.md 控制在 20KB 以内。说明书里只放规则和入口，玩法细节写进 `Documents/<专题>.md`，说明书链接过去。
- 建 `Documents/concept.md` 作为设计真相，同样分三栏。

## 逻辑和画面分家
- 借鉴或使用 MVC/MVP 框架，代码架构采用“数据-对象-管理/控制”的分层设计思想。
- 逻辑层不碰画面表现层的代码，事件解耦。
- 大类按功能拆成多个文件；一个文件要翻页才能找到东西，就拆。
- 工程需要手动登记源文件时，写脚本自动登记，不要手改。
- 编辑器和调试工具不进发行版。

## 内容全是数据
- `Content/data/*.json`：所有数值。改数值只改 JSON，不改代码。
- `Content/i18n/ui.csv`：所有界面文字，至少中、英两列；代码里不写死文案。
-  美术源文件（如 .aseprite）运行时直接读取，或由脚本导入，不手工导出。
-  音效、特效等资源 key 集中登记在一个文件里。
- 调试面板改的数值写回源目录的 JSON，不写构建输出目录里的副本。
