# 玩家角色控制（状态机实现）

> 本文只写**已经做出来的东西**：玩家能做什么、代码怎么实现的、为什么采用这种设计。
> 手感数值和键位都会变，本文不写死它们，只指出在哪个表里；具体数值以
> `Assets/Resources/Content/data/*.json` 为准（`tools/verify-content.ps1` 会校验）。
>
> 适用版本：2026-11-14（含空中冲刺）。角色：Blitz（Spine 骨骼动画）。

---

## 1. 玩家现在能做什么

| 动作 | 默认按键 | 触发条件 | 结果 |
| --- | --- | --- | --- |
| 左右移动 | `A` / `D` | 水平输入超过死区 | 以 `moveSpeed` 水平移动，自动转身 |
| 跳跃 | `Space` | **在地面上**按下的那一帧 | 给刚体一个 `jumpForce` 的向上初速度，之后由重力接管 |
| 冲刺 | `LeftShift` | 冷却结束 + 按下的那一帧，**地面与空中都可以** | 朝当前朝向以 `dashDistance / dashDuration` 的速度冲 `dashDuration` 秒 |
| 射击（连射） | 鼠标左键按住 | `Attack_Loop` 动画的 `OnAttack` 事件 | 每次事件出一发特殊弹；松开后收枪 |
| 近战 | `F` | 按下的那一帧 | 播 `Skill_02` 单次动画，期间原地不动（目前只有动画，没有判定） |

按键不是写死在代码里的，来自 `Content/data/input.json`；上表的默认值就是该文件的初始内容。

### 没有做的（避免误会）

- 玩家没有受击、硬直、死亡状态；
- 近战没有伤害判定；
- 没有二段跳、没有冲刺残影；
- 没有移动端触屏操作（见 `Documents/拍板记录.md` 的「待决定」）。

## 2. 结构：谁负责什么

一次「按下空格」要经过三层，各层边界是编译期强制的（三个 asmdef）：

| 层 | 位置 | 职责 | 本次相关的内容 |
| --- | --- | --- | --- |
| Core（纯 C#，不引用 UnityEngine） | `Assets/Scripts/Core/` | 数值 DTO + 纯逻辑规则 | `PlayerTuning`（数值）、`DashCooldown`（冷却计时）、`Health`（标靶用） |
| Framework | `Assets/Scripts/Framework/` | 读内容表、存档 | `ContentLoader`（`Resources.Load` + LitJson） |
| Game | `Assets/Scripts/Game/` | 把数值接到引擎对象上 | `PlayerController`、`PlayerInputReader`、6 个状态、Spine 封装、枪口 |

数据流：

```
player.json / input.json / assets.json
        │  ContentLoader（懒加载一次，缓存进 GameContent）
        ▼
PlayerTuning / InputTuning / SpineAnimations
        │
        ├──► PlayerInputReader.Poll()      每帧把设备状态变成「轴 / 按住 / 刚按下」
        └──► PlayerController.Tuning       状态里读数值
                    │
                    ▼
             StateMachine.Tick()  ──► 当前状态决定「要不要换状态」「怎么动」
                    │
                    ▼
        Rigidbody2D.velocity / Spine 动画 / 枪口位置
```

关键点：**状态里没有一个写死的数字**。`0.01` 这类纯数学保护量（物理 epsilon、除零下限）留在代码里并写注释，不算可调数值——这条是 `AGENTS.md` 硬约定的边界。

## 3. 状态机骨架

三个文件撑起整个骨架，它们在 `Assets/Scripts/Game/Player/States/`：

### 3.1 `IState`：四个生命周期方法

```csharp
void Enter();       // 进入时：播动画、给初速度、清零计时
void Tick();        // 每渲染帧：读输入、判断要不要换状态
void FixedTick();   // 每物理帧：改刚体速度
void Exit();        // 离开时：收尾（停水平速度、退订动画事件）
```

拆成 `Tick` 和 `FixedTick` 是有原因的两个时钟：

- **改速度必须在 `FixedUpdate` 里做**，否则物理帧率与渲染帧率不一致时移动距离会抖；
- **读输入、判断状态切换要跟着渲染帧走**，否则 30fps 机器上连点会被吞。
- `PlayerController` 里 `Update()` 调 `_machine.Tick()`，`FixedUpdate()` 先刷新落地状态再调 `_machine.FixedTick()`——**落地判定先于状态机**，这样跳跃状态在同一次物理帧里就能用上最新的 `IsGrounded`。

### 3.2 `StateMachine`：只做三件事

```csharp
public IState Current { get; private set; }
public IState Previous { get; private set; }
public void ChangeState(IState next, bool force = false)  // null 忽略、同一状态忽略（除非 force）
```

它**不**维护转移表，也**不**知道状态之间怎么走。切换条件写在每个状态自己的 `Tick()` 里：

```csharp
// PlayerIdleState.Tick()
if (inputs.DashPressed && Player.CanDash) { Machine.ChangeState(Player.DashState); return; }
if (inputs.JumpPressed && Player.IsGrounded) { Machine.ChangeState(Player.JumpState); return; }
...
```

**为什么这样设计（状态自治）**：

1. **新增一个状态只需要改两处**：新建一个类 + 在相关状态的 `Tick` 里加一条 `if`。不用回头维护一张巨大的转移表，也不会出现「表里漏写一条边导致某状态进得去出不来」。
2. **每个状态的完整行为在一个文件里读得完**：什么时候进、进来播什么动画、每帧怎么动、什么时候走，全部相邻。排查「为什么冲刺时不能跳」只要看 `PlayerDashState.cs`，不用在表和控制流之间来回跳。
3. **代价是知识分散**：同一个输入（比如 `JumpPressed`）在 Idle / Move / Jump 里各判一次，改优先级要动多个文件。目前只有 6 个状态、每处 3~5 行，这个代价可以接受；如果状态数上到十几个，再考虑把「优先级」抽成一张表。

`ChangeState` 忽略重复切换是刻意的：`Tick` 里每帧都可能满足同一条条件，重复 `Enter` 会反复重播动画、反复给初速度。真正需要「原地重来」的地方只有两处，都显式传了 `force`：

- `PlayerController.Start()` 强制进 `IdleState`（第一次进入没有 Previous）；
- 射击收枪期间再按扳机 → `ChangeState(Player.AttackState, true)`，重播 `Attack_Begin` 保证连点手感。

### 3.3 `PlayerState`：缓存两个引用

```csharp
protected readonly PlayerController Player;
protected readonly StateMachine Machine;
```

状态是**普通 C# 类**，不是 MonoBehaviour：它们不挂在 GameObject 上，由 `PlayerController.Awake()` 一次性 `new` 出来并缓存到 `IdleState`/`MoveState`/… 属性里。
这样做的原因是：状态本身没有引擎生命周期需求（不需要 `Update`，由控制器统一驱动），做成 MonoBehaviour 会多出 6 个组件、多一层执行顺序问题，还没法在编辑器里单看一个状态的行为。

## 4. 六个状态逐个说

### 4.1 Idle（待机）

- **进入**：播 `Idle` 循环；
- **每帧**：按固定优先级检查冲刺 → 跳跃 → 近战 → 射击 → 移动；
- **物理帧**：`MoveHorizontal(0f, 1f)`，把水平速度压成 0（不是直接置 0，走同一条速度通道，避免与其他状态的速度写法不一致）。

为什么优先级是「冲刺 > 跳跃 > 近战 > 射击 > 移动」：越「不可打断/位移性强」的动作越靠前。冲刺优先级最高是因为它有冷却、玩家按下就期待立刻位移；移动放最后，因为它是「默认动作」，前面都没触发才走。

### 4.2 Move（移动）

- **进入**：播 `Move` 循环；
- **每帧**：与 Idle 同样的优先级，另外「水平输入回到死区内」→ 回 Idle，否则 `FaceTo(MoveAxis)`；
- **物理帧**：`MoveHorizontal(MoveAxis, 1f)`。

### 4.3 Jump（跳跃 / 滞空）

- **进入**：播 `Idle` 动画（Spine 资源里没有跳跃动作，按需求用 Idle 代替），调 `Player.Jump()` 施加上跳初速度，`_airTime = 0`；
- **每帧**：先判冲刺（`DashPressed && CanDash` → `DashState`），再 `FaceTo`，**不响应射击/近战**——空中开枪会让「跳跃中连射」变成一条没人验证过的路径，当前明确不做；
- **物理帧**：`_airTime += fixedDeltaTime`；保留空中水平操控；三重落地条件全部满足才切回地面状态：

  ```csharp
  if (_airTime < Player.Tuning.minAirTime) return;   // 起跳瞬间脚还贴地，防误判
  if (!Player.IsGrounded) return;
  if (Player.Body.velocity.y > 0.01f) return;        // 还在上升，防“刚起跳就落地”
  ```

`minAirTime` 是**滞空保护时间**：刚起跳时脚底圆检测仍会命中地面，不挡住就会瞬间「落地」，状态在 Jump/Idle 之间抖。这个值以前是代码里的常量，现在进了 `player.json`，因为它直接影响手感（跳得「黏不黏地」）。

#### 空中冲刺（2026-11-14 加）

原来 `JumpState` 根本不读 `DashPressed`，所以一起跳冲刺键就失效。现在：

- `Tick()` 里加冲刺分支，条件与地面完全相同；
- 空中冲刺结束如果**还没落地**，不是回 Idle/Move（那两个状态没有落地逻辑，会卡在「站在空中」），而是调 `PlayerJumpState.ContinueAirborne()` 回到滞空状态。

`ContinueAirborne()` 做了三件容易踩坑的事：

```csharp
public void ContinueAirborne()
{
    _resumeInAir = true;        // 下次 Enter 是“续接”，不是“新起跳”
    Machine.ChangeState(this);
}

public override void Enter()
{
    Player.Animation.Play(PlayerAnimations.Idle, true);

    if (_resumeInAir)
    {
        _resumeInAir = false;
        _airTime = Player.Tuning.minAirTime;   // ① 不再等 minAirTime，否则落地判定被推迟
        return;                                 // ② 不调 Player.Jump()，否则每次冲刺都被再弹一下
    }

    Player.Jump();
    _airTime = 0f;
}
```

③ 冷却不用管：`DashCooldown` 在 `PlayerController.Update` 里每帧计时，与当前状态无关，所以空中冲刺天然和地面共用同一条冷却，**没有新增任何数值字段**。

垂直方向也不动：`ApplyDashVelocity()` 只写 `velocity.x`，`velocity.y` 保持原值，空中冲刺是「水平窜出去 + 继续下落」，不是悬停。

### 4.4 Dash（冲刺）

- **进入**：播 `Move` 动画（无专用冲刺动作），`Player.BeginDash()` → 启动冷却 + 立刻施加一次冲刺速度，`_elapsed = 0`；
- **每帧**：累加 `_elapsed`，到 `DashDuration` 后看是否落地——没落地走 `ContinueAirborne()`，落地了按输入回 Move/Idle；
- **物理帧**：`ApplyDashVelocity()`，**每物理帧重写**水平速度为 `Facing * DashSpeed`，而不是只给一次冲量或 `AddForce`。原因：地面摩擦力、之前的惯性、碰撞后的速度衰减都会污染冲刺距离；每帧硬写才能保证 `dashDistance` 真的等于「速度 × 时间」；
- **退出**：`StopHorizontalMovement()`，避免冲刺速度残留成走路速度。

冲刺期间**锁定方向与输入**：不读移动输入、不转身、不能跳、不能开枪。玩家在 0.2 秒里按别的键一律忽略——这是「位移型动作」的常规处理，否则会出现冲刺中途反向的鬼畜画面。

### 4.5 Attack（射击）

动画三段：`Attack_Begin`（抬枪）→ `Attack_Loop`（循环）→ `Attack_End`（收枪）。

- **进入**：`StopHorizontalMovement()`（射击原地不动），订阅 `SpineAnimationPlayer.SpineEvent`，播 `Attack_Begin` 并 `Queue` `Attack_Loop`；清 `_hasFired` / `_finishing`；
- **每帧**：允许原地转身（子弹跟着枪口方向走，但不产生位移）；**射速完全由动画事件决定**：

  ```csharp
  private void OnSpineEvent(string animationName, string eventName)
  {
      if (_finishing) return;
      if (animationName != PlayerAnimations.AttackLoop) return;
      if (eventName != PlayerAnimations.AttackEvent) return;   // "OnAttack"

      _hasFired = true;
      Player.FireSpecial();
  }
  ```

  即：`Attack_Loop` 每循环一次、动画里的 `OnAttack` 事件触发一次 → 出一发。**不是每帧开火，也不是固定计时器**。好处是「射速」这个手感参数天然跟着动画走：改动画时长或换动画，射速自动跟着变，不会出现「动画慢吞吞、子弹却泼水」的脱节。
- **松开扳机**：`_hasFired && !AttackHeld` → 播 `Attack_End`，用 `GetDuration(Attack_End)` 当收枪计时，结束时回地面状态；
- **短点击的边界**：如果松手时还一发都没出（点击快于 `Attack_Begin`），不立刻收枪，而是等第一次 `OnAttack` 出弹后再收。否则「快速点一下」会变成完全不放枪；
- **收枪期间再按**：`ChangeState(AttackState, true)` 重新进入，连点不会卡在收枪动画里；
- **退出**：退订动画事件（`_subscribed` 标志防重复订阅）。

为什么用事件而不是 `if (timer >= interval) Fire()`：一是上面说的与动画同步；二是「枪口火光」也挂在同一个事件上（见第 7 节），射击的视觉与判定来自同一个事实，不会各算各的。

### 4.6 Melee（近战）

- **进入**：停下水平移动，播 `Skill_02`（单次），`_duration = max(GetDuration(Skill_02), 0.1f)`；
- **每帧**：计时到 `_duration` → 按输入回 Move/Idle；
- **物理帧**：持续 `StopHorizontalMovement()`，期间完全锁死（不响应移动、跳跃、冲刺、射击）。

`Mathf.Max(..., 0.1f)` 是保护量：动画时长读不到（资源改名/动画缺失）时至少锁 0.1 秒，避免同一帧内进出造成死循环。

                    │             Idle             │
                    └──┬────┬────┬────┬────┬───────┘
        冲刺(冷却好)     │    │跳跃│    │近战│射击   │有移动输入
                        ▼    │    ▼    ▼    ▼        ▼
                    ┌──────┐ │ ┌────┐┌────┐┌──────┐┌──────┐
                    │ Dash │ │ │Jump││Melee││Attack││ Move │
                    └──┬───┘ │ └─┬──┘└─┬──┘└──┬───┘└──┬───┘
                       │     │   │     │      │       │
     落地 → Move/Idle  │     │   │     │      │       │ 松键 → Idle

用文字说清优先级（同一帧多个输入同时按下时，先命中的生效，后面的丢掉）：

| 当前状态 | 判定顺序 |
| --- | --- |
| Idle / Move | 冲刺 → 跳跃 → 近战 → 射击 →（Move 额外：无输入回 Idle） |
| Jump | 冲刺 →（转身）；落地 → Move / Idle |
| Dash | 计时结束 →（未落地：滞空；落地：Move / Idle） |
| Attack | 收枪中再按 → 重进 Attack；松手 → 收枪 → Move / Idle |
| Melee | 计时结束 → Move / Idle |

## 6. 输入层：为什么是「轮询」而不是事件回调

`PlayerInputReader` 基于 **Input System Package**（`Keyboard.current` / `Mouse.current`），由 `PlayerController.Update()` 每帧调一次 `Poll()`。

```csharp
public void Poll()
{
    var previousJumpHeld = _jumpHeld;          // 先存上一帧
    ...
    _jumpHeld = InputBindings.IsHeld(keyboard, _bindings.jump);
    _jumpPressed = _jumpHeld && !previousJumpHeld;   // 边沿自己算
}
```

三个设计决定：

1. **轮询而不是 `PlayerInput` 的 `SendMessage`/回调**：状态机需要一个「这一帧的事实快照」——`MoveAxis`、`AttackHeld`、`JumpPressed` 必须来自同一帧，各状态读到的值才一致。回调方式下，事件在别的时机进来，改的是同一个字段，很难保证「一帧内不变」；而且回调要配 Action Asset，键位就跑到 `.inputactions` 里去了，与「键位进 JSON」冲突。
2. **边沿（`Pressed`）自己算**：Input System 有 `wasPressedThisFrame`，但它与 `Poll()` 的调用时机耦合（同一帧多调一次就变成 false）。自己存上一帧状态最稳，也让调试覆盖（下面）走完全相同的路径。
3. **键位解析拆到 `InputBindings`**：`PlayerInputReader` 只做「读」，`InputBindings` 做「字符串 → `Key` / `MouseButton?`」。这样换键是纯数据操作（改 `input.json`），解析失败时退回默认键并 `Debug.LogError`，不会一改表就崩。

### 调试覆盖

`PlayerInputReader` 上有 `useOverride / overrideMoveAxis / overrideAttackHeld / ...` 一组字段和 `SetOverride(...)` 方法，可以在没有真实输入时驱动角色（无人值守跑状态机流程用）。整段用 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 包住，发行版里 `OverrideEnabled` 恒为 false、`SetOverride` 是空操作。这是 `tools/serialized-number-allowlist.txt` 里唯一被允许出现在组件上的数值字段，理由是它不是手感数值。

## 7. 数值与规则：冷却为什么不在状态里

| 文件 | 字段 | 影响 |
| --- | --- | --- |
| `player.json` | `moveSpeed` | 移动速度 |
| | `jumpForce` | 起跳初速度 |
| | `groundCheckRadius` | 脚底检测圆半径（地面判定灵敏度） |
| | `dashDistance` / `dashDuration` | 冲刺距离 / 时长（速度 = 距离 ÷ 时长） |
| | `dashCooldown` | 冲刺冷却（从**冲刺开始**计时，不是从结束） |
| | `moveDeadzone` | 输入死区，低于它视为「没有移动输入」 |
| | `minAirTime` | 最小滞空时间，防止起跳瞬间误判落地 |
| `input.json` | 6 个绑定 | 键位（`a`/`d`/`space`/`leftShift`/`f`/`leftButton`） |
| `assets.json` | `spine.animations.*`、`spine.muzzleBone` | 动画名、枪口骨骼名 |

**冲刺冷却放在 `PlayerController` 而不是状态里**：

```csharp
// PlayerController.Update()
_dashCooldown.Tick(Time.deltaTime);
```

- 冷却要跨状态有效：冲刺结束后进 Idle/Move/Jump，计时必须继续走。放在 `PlayerDashState` 里，退出状态就断了。
- `DashCooldown` 本身是 `Core/Rules` 下的纯 C# 类（`Configure / Start / Reset / Tick`，`IsReady => _remaining <= 0f`），不引用 UnityEngine，可以脱离引擎测试。
- 计时用**真实时间**而不是物理时间：冲刺冷却不该受 `timeScale` 或物理帧率影响。

`PlayerController` 还集中了几个「所有状态都要用」的查询：`IsGrounded`、`HasMoveInput`（读死区）、`CanDash`、`DashSpeed`、`Facing`。状态只读这些，不各自实现一遍，避免同一概念两套算法。

## 8. 几个容易被问到的实现选择

### 8.1 落地检测为什么是「脚底小圆」而不是碰撞回调计数

```csharp
var bounds = _capsule.bounds;
var checkPoint = new Vector2(transform.position.x, bounds.min.y);
var count = Physics2D.OverlapCircleNonAlloc(checkPoint, Tuning.groundCheckRadius, _groundHits);
// 跳过：自己、自己的子物体、触发器
```

- 用 `OnCollisionEnter/Exit` 计数，碰到「同时压两块砖」时退出顺序会让计数错乱，出现「站在地上却被判成空中」；
- 用触发器判地面，要和所有平台配 `isTrigger` 检测层，场景里多一层布线；
- 脚底圆检测是**无状态**的：每物理帧重新问一次「脚下有没有非触发器碰撞体」，不会被历史计数污染，也不怕斜坡/两块平台接缝。
- 用 `OverlapCircleNonAlloc` + 预分配 8 格数组，避免每帧产生垃圾（80Hz 物理帧下 GC 会很明显）。

### 8.2 转身为什么只翻视觉根节点

```csharp
var scale = visualRoot.localScale;
scale.x = Mathf.Abs(scale.x) * direction;
visualRoot.localScale = scale;
```

翻 `Animation` 的 transform，不动 `CapsuleCollider2D`、不动 `Rigidbody2D`。翻碰撞体会让胶囊偏移方向跟着变，撞墙瞬间被弹开；翻刚体更糟，物理接触点全乱。视觉与碰撞分家是 2D 角色转身的标准做法。

### 8.3 为什么「开火」要广播事件而不是自己闪火光

```csharp
Fired?.Invoke(Facing, special ? bullet.ShotColor : Color.white);
```

控制器只声明「刚刚打了一发、朝向是哪边、这一发什么颜色」，**不碰 `SpriteFlash`**。枪口火光由 `MuzzlePoint` 订阅 `Fired` 自己播。这样加音效、加手柄震动、加弹壳，都只是「再加一个订阅者」，开火逻辑一行都不用改（`AGENTS.md` 硬约定第 11 条）。

### 8.4 子弹为什么由「动画事件」而不是「按住就一直射」

见 4.5。核心是让射速与动画同步；另外 `Attack_Loop` 循环期间一直按住也只在 `OnAttack` 那一下出弹，不会出现「按住 1 秒打出 60 发」。

## 9. 想改的时候改哪里

| 想做的事 | 改哪里 | 要注意 |
| --- | --- | --- |
| 调手感（速度、跳跃力、冲刺距离/冷却、死区、滞空时间） | `Content/data/player.json` | 改完跑 `tools/verify-content.ps1`；改 JSON 不需要重新编译，但要**退出 Play 再进**（`ContentLoader.Current` 有缓存） |
| 换键位 | `Content/data/input.json` | 值是 `Key` 枚举名（`space`、`leftShift`、`f`…）；鼠标写 `leftButton`/`rightButton`/`middleButton`；写错会在 Console 报错并退回默认键 |
| 换动画 / 骨骼名 | `Content/data/assets.json` | 动画名必须与 Spine 资源里一致，写错不会崩，但会看到角色不动（`SpineAnimationPlayer.Play` 找不到动画） |
| 加一个新动作（比如翻滚） | ① `States/` 下新建 `PlayerRollState.cs`（继承 `PlayerState`）；② 在 `PlayerController.Awake` 里 `new` 出来并加个属性；③ 在允许触发的状态 `Tick` 里加一条 `if` | 如果要新的可调数值，先加进 `player.json` 和 `PlayerTuning`，再让状态读 `Player.Tuning.xxx`；不要在状态里写常量 |
| 加一个新的输入（比如格挡） | `input.json` + `InputTuning` + `InputBindings`（解析）+ `PlayerInputReader`（轮询）+ 状态里判断 | 解析和轮询要分开写，别把字符串解析塞回 `Poll()` |

## 10. 已知限制

- **跳跃用 `Idle` 动画、冲刺用 `Move` 动画**：Spine 资源里没有对应动作，不是代码没写。
- **近战只有动画没有判定**：`Skill_02` 播完就回 Idle，没有攻击盒、没有伤害。
- **空中不能射击/近战**：`JumpState` 明确不响应这两类输入（见 4.3），属于当前取舍，不是漏写。
- **没有受击/死亡**：玩家不会被打断，也没有生命值。
- **移动端不可玩**：只有键鼠绑定；触屏需要虚拟摇杆与开火按钮，属新功能，待拍板。
