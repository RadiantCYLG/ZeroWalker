# 瞄准与准星

> 本文只说「瞄准」这件事：准星长什么样、为什么在那儿、子弹为什么朝那儿飞。
> 玩家其它动作见 [玩家角色控制.md](玩家角色控制.md)；决策理由见 [拍板记录.md](../拍板记录.md)。

## 1. 现在能做什么

| 操作 | 触发条件 | 看到什么 / 发生什么 |
| --- | --- | --- |
| 按住鼠标右键 | `input.json` 的 `aim`（默认 `rightButton`） | 屏幕出现一个白色圆环，环心一个白点；圆环跟着鼠标走，任何分辨率都贴着指针 |
| 瞄准时按左键射击 | `Attack_Loop` 的 `OnAttack` 动画事件 | 子弹从枪口出发，朝「准星指的那个世界点」飞；开火瞬间角色转向准星那一侧 |
| 不按右键直接射击 | 同上 | 子弹沿角色面朝方向平射（老行为，不变） |
| 松开右键 | — | 准星消失，射击恢复平射 |

准星不是世界里的物体，也不参与任何判定：它只是「鼠标现在在哪」的可视化。真正决定子弹方向的是同一次采样得到的屏幕坐标。

## 2. 数据从哪来

| 数据 | 文件 | 字段 |
| --- | --- | --- |
| 瞄准键 | `Content/data/input.json` | `aim`（鼠标键名：`leftButton` / `rightButton` / `middleButton`） |
| 第二个冲刺键 | `input.json` | `dashSecondary`（默认 `space`，与瞄准同一批改动加入） |
| 准星外圈直径 | `Content/data/ui.json` | `aimRingSize`（默认 64 像素） |
| 准星中心点直径 | `ui.json` | `aimDotSize`（默认 6 像素） |

尺寸单位是「Canvas 参考分辨率下的像素」。画布用 `CanvasScaler`（Scale With Screen Size，参考 1920×1080），所以 1080p 下 64px 就是 64 个屏幕像素，4K 下会等比放大，视觉大小一致。

改数值后要**退出 Play 再进**——`ContentLoader.Current` 是静态缓存，不会热重载。

## 3. 三层分工

```
PlayerInputReader            AimHeld、AimScreenPosition（屏幕坐标，像素）
      │
      ├──► PlayerController.TryGetAimDirection  屏幕点 → 世界方向 → Bullet.Launch
      │
      └──► AimReticleView                       屏幕点 → 画布坐标 → 准星位置
```

三者的关系是「同一份输入，两个消费者」：

- **InputReader**（`Game/Player/PlayerInputReader.cs`）：每帧 `Poll()` 里 `AimHeld = _bindings.ReadAim();`、`AimScreenPosition = mouse.position.ReadValue();`。它不知道准星长什么样，也不知道子弹往哪飞。
- **Controller**（`Game/Player/PlayerController.cs`）：`Fire()` 里若 `Inputs.AimHeld && TryGetAimDirection(out var aim)` 就用 `aim` 当方向，否则用 `Facing`。它不碰 UI。
- **View**（`Game/UI/AimReticleView.cs`）：只在 `AimHeld` 为真时显示，把 `root.anchoredPosition` 设到鼠标位置，并按 `ui.json` 设尺寸。它不碰子弹。

这样以后换准星美术、加「瞄准时镜头拉近」、加手柄右摇杆瞄准，都只动其中一层。

## 4. 屏幕点怎么变成子弹方向

```csharp
// PlayerController.TryGetAimDirection
var from = muzzle.WorldPosition;                               // 枪口（世界坐标）
var depth = Mathf.Abs(camera.transform.position.z - from.z);    // 相机到枪口平面的距离
var world = camera.ScreenToWorldPoint(new Vector3(screen.x, screen.y, depth));
var direction = ((Vector2)(world - from)).normalized;
```

三个关键点：

1. **深度取「相机到枪口的 z 差」**。`ScreenToWorldPoint` 需要知道这个点离相机多远；正交相机下，取角色所在平面的深度，算出来的世界点就正好落在角色那一层，准星看着指哪儿、子弹就打哪儿。若偷懒传固定值，相机一动（Cinemachine 会动）方向就会偏。
2. **方向与朝向解耦**。`Facing` 只决定身体朝哪边站；子弹方向由几何决定。开火时把 `Facing` 翻到准星那一侧，是为了不让角色「背对目标开枪」——这是表现层的顺手修正，不影响方向本身。
3. **退化情况退回平射**。没有相机、没有枪口、或准星与枪口重合（`delta.sqrMagnitude < 1e-6`）时返回 `false`，`Fire()` 用 `Facing` 平射。没有鼠标的设备按扳机仍是老行为，不会射出零向量。

子弹本身不知道「瞄准」这回事：`Bullet.Launch(direction, side, special)` 只认一个单位向量，瞄准与平射的区别只在这一步之前。

## 5. 准星 UI 是怎么生成的

菜单 **`ZeroWalker/生成瞄准准星 UI（UGUI）`**（`Assets/Editor/AimReticleSetup.cs`）一次做完：

1. 在 `Assets/ArtRes/UI/` 下画两张纯白 PNG：
   - `ReticleRing.png`（128×128，外径 120、线宽 6、边缘 1px 抗锯齿）；
   - `ReticleDot.png`（16×16 实心圆，边缘抗锯齿）。
   两张都是「白色 + 透明度」，颜色交给 `Image.color` 乘，所以换色不用重画图。
2. 找场景里已有的 `Canvas`，没有就新建 `HUD`（Screen Space - Overlay、`sortingOrder = 10`、`CanvasScaler` 参考 1920×1080）。
3. 在画布下建 `AimReticle`（`Image` 用圆环）+ 子物体 `Dot`（`Image` 用圆点），两个 `Image` 都 `raycastTarget = false`（不挡点击）。
4. 挂 `AimReticleView`，用 `SerializedObject` 填 `root` / `ring` / `dot` / `canvas` / `input`。
5. 按 `ui.json` 摆好初始尺寸，`SetActive(false)`，保存场景。

幂等：重复跑会复用画布、重建 `AimReticle`；但**生成的 PNG 不会被覆盖**——想换造型就直接改这两张图。

## 6. 屏幕坐标怎么落到画布上

```csharp
// AimReticleView.FollowPointer
RectTransformUtility.ScreenPointToLocalPointInRectangle(parent, screenPosition, camera, out var local);
root.anchoredPosition = local;
```

- Overlay 画布传 `null` 相机（`camera` 变量只对 Screen Space - Camera / World 模式非空）。
- 用 `ScreenPointToLocalPointInRectangle` 而不是直接写 `root.position = screenPoint`：前者在任意 `CanvasScaler` 设置、任意锚点下都成立，后者依赖「画布世界单位恰好等于像素」这个隐含前提。

## 7. 为什么是 UGUI，不是世界里的 Sprite

| 方案 | 结果 |
| --- | --- |
| 世界 Sprite（放在角色前方） | 会随相机缩放、跟着角色走位漂移，2.5D 透视下很难和鼠标对齐 |
| UGUI Overlay 画布（现在） | 永远贴屏幕，位置就是鼠标像素；分辨率变化由 `CanvasScaler` 统一处理 |

代价是它不进 `sortingOrder` 体系（永远画在最上层），挡不住任何游戏物体——对「准星」来说正是想要的。

## 8. 边角情况

- **没有鼠标设备**：`AimHeld` 恒为 false，准星不显示，射击平射。
- **调试覆盖输入**（`SetOverride`，仅编辑器/开发版）：`AimHeld = false`、`AimScreenPosition = 屏幕中心`，避免调试时准星乱跳。
- **暂停 / 时间缩放**：准星在 `Update` 里更新，跟着渲染帧走；游戏逻辑用了物理帧，两者互不影响。
- **窗口失焦**：Input System 拿不到指针位置时沿用最后一帧的值，准星会停在原地，不影响开火逻辑（`AimHeld` 会变 false）。

## 9. 怎么调

| 想做的事 | 改哪里 |
| --- | --- |
| 准星太大/太小 | `ui.json` 的 `aimRingSize`、`aimDotSize`（像素，按 1920×1080 参考） |
| 换准星颜色 | 场景里 `AimReticle` / `Dot` 的 `Image.color`（白图乘色，任意色都行） |
| 换准星造型 | 改 `Assets/ArtRes/UI/ReticleRing.png` / `ReticleDot.png`（保持透明背景） |
| 换瞄准键 | `input.json` 的 `aim`（必须是鼠标键名；写成键盘键会报错并退回右键） |
| 换第二个冲刺键 | `input.json` 的 `dashSecondary` |
| 让准星带吸附/回中 | 目前没有；要在 `AimReticleView.FollowPointer` 里对 `local` 做处理，并且 `TryGetAimDirection` 要用同一个处理后的点，否则「看着在这儿、打向那儿」 |

## 10. 已知限制

- **只有鼠标能瞄准**：移动端没有指针，准星会停在屏幕中心（`AimHeld` 也为 false），射击只能平射。触屏瞄准（拖拽/双摇杆）属于待决定项。
- **准星不避让 UI**：Overlay 画布上没有别的 HUD，暂时不存在遮挡问题；以后加血条/按钮，需要注意 `sortingOrder`。
- **没有射线检测**：准星不指示「会打中什么」，也不高亮敌人；子弹是否命中由飞行途中的触发器决定。
- **反投影假设角色与枪口在同一 z**：如果以后做多层纵深（不同 z 的角色），深度要按目标层重算。
